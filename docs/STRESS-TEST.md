# 连续 2 小时压力测试清单

目标：`node server/index.js` 连续运行 120 分钟，链路（平板帧 → 推理 → 大屏广播）不中断，内存无持续泄漏，丢帧策略生效。

## 自动化客户端

```bat
npm run stress -- --minutes=120 --clients=3
```

模拟 3 台平板每 400ms 上传 160×160 PNG，并挂一个模拟大屏。每 30 秒打印一次统计：

```
[300s / 剩余6900s] route=onnx 入帧=2250 丢弃=1980 推理=270 均耗时=31ms 错误=0 heap=68MB rss=190MB ...
```

冒烟测试可先跑 `--minutes=5`。

另一个终端全程观察：

```bat
curl http://127.0.0.1:3000/api/status
```

主持页 `/host` 也可看实时面板。

## 关键判据

| 指标 | 期望 | 异常处理 |
| --- | --- | --- |
| `stats.framesDropped` | 随运行时间**持续增长**（忙时丢旧帧生效） | 若为 0 且推理耗时 > 400ms，检查单槽队列是否被阻塞 |
| `stats.errors` | 保持 0 | 非 0 查服务端日志的"帧处理失败"行 |
| `memMB.heapUsed` | 前 20 分钟稳定在某个区间，之后不单调上升 | 持续上升检查张量 `dispose()` 与 PNG 缓冲引用 |
| `memMB.rss` | 允许小幅波动，不翻倍 | 翻倍检查原生绑定是否泄漏 |
| `stats.avgInferMs` | 明显低于 `intervalMs`(400) | 接近或超过 400 说明推理成为瓶颈，应降低输入尺寸或换路线 |
| WebSocket 连接数 | 平板 3 / 大屏 1 | 掉线后应自动恢复 |
| 页面表现 | 大屏 Top-5 持续更新，无卡死 | 检查浏览器控制台 |

> 注意：Node 的 GC 不是即时的，`heapUsed` 锯齿状波动属正常；判断是否泄漏要看**回收后的谷值**是否逐小时抬高。

## 时间表

### T+0 ~ T+10 分钟：基线

- [ ] 服务启动，`/api/status` 显示预期路线，记录 `attempts` 与实际 `route`
- [ ] 打开 `/draw`、`/display`、`/host` 三页，确认连接数正确
- [ ] 启动压测客户端，记录初始 `framesIn / inferences / heapUsed / rss`
- [ ] 人工开始一轮，确认大屏出现 Top-5 与置信度条
- [ ] 确认榜首变化时有翻转动画

### T+10 ~ T+30 分钟：负载建立

- [ ] `framesDropped` 开始增长，说明丢帧生效
- [ ] `errors` 仍为 0
- [ ] 观察 3 台模拟平板与 1 个大屏的连接数是否稳定
- [ ] 人工点一次「立即锁定结算」，确认锁定特效与结算文案
- [ ] 确认结算后新回合能正常开始（锁定状态被重置）

### T+30 ~ T+60 分钟：内存观察

- [ ] 记录第 30、45、60 分钟的 `heapUsed` 谷值，画成简单曲线
- [ ] 若谷值增幅 > 20MB/小时，标记为疑似泄漏，准备复现
- [ ] 检查任务管理器中 Node 进程句柄数是否稳定
- [ ] 手动断开一台平板模拟客户端，确认服务端连接数下降并能重新接入

### T+60 ~ T+90 分钟：故障注入

- [ ] 停掉一个客户端 Wi-Fi（或关闭对应进程 10 秒）：确认平板页显示重连提示，恢复后自动连上
- [ ] 关闭大屏页面再打开：确认大屏重新收到 `hello` 与当前回合状态
- [ ] 把 `config.json` 的 `decoyMode` 改为 true 并重启：确认骗AI模式生效（正确答案被压制），随后改回 false
- [ ] 重命名 `model/model.json`（仅当前路线为①或③时）：确认服务不崩溃、自动降级并记录失败原因，随后恢复
- [ ] 触发一次超时结算（不点锁定，等满 70 秒）：确认文案为「AI 翻车，人类得分」

### T+90 ~ T+120 分钟：长稳

- [ ] 继续观察 `errors === 0`
- [ ] 确认 `avgInferMs` 没有明显劣化（相比基线增加 < 30%）
- [ ] 确认比分持续累计且没有串轮（每轮只有一次结算）
- [ ] 记录第 120 分钟内存数据，与基线对比

### 收尾

- [ ] 停止压测客户端（Ctrl+C 或等脚本自动结束）
- [ ] 导出 `/api/status` 的 `log` 字段留存
- [ ] 重启服务，确认比分归零、无残留状态（验证"不落盘"）
- [ ] 检查 `model/` 与 `assets/` 之外没有生成任何画布帧或日志图片文件

## 故障注入后的必查项

1. 模型加载失败时：平板是否显示录屏 + 人工裁判提示；大屏是否显示降级徽章。
2. 平板断连时：大屏底部是否出现"平板断连，等待自动重连…"。
3. 服务重启时：两端是否都出现全屏断连遮罩并自动恢复。
4. 任何情况下都不应把画布帧写入磁盘或发到外网；可在防火墙日志中确认无出站请求（npm 安装阶段除外）。
